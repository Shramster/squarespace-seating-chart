## Backend / Integrations

- [x] ~~Seat hold + precise per-seat checkout link~~ — clicking Reserve created a short-lived `SeatHold` (10 min TTL) via `POST /api/shows/<sku>/seats/<code>/hold/`, so the seat map showed held seats as unavailable to other browsers while `ReservePanel` sent the buyer to checkout for their exact seat. The precise-checkout-link half stands; the hold half was removed later — see below.
- [x] Per-seat Squarespace permalinks — catalog restructured from one product per show (with a seat-picker variant) to one product per seat, grouped by show day via `Categories`. Reserve now opens `seatBuyLink()` — a direct permalink to that seat's own product page, no dropdown. Squarespace has no native URL parameter for preselecting a variant, so this made the deferred cart-injection spike below unnecessary: same UX win (no manual seat hunting at checkout) without touching Squarespace's undocumented internal cart JS. See `RUNBOOK.md`.
- [x] ~~Spike: same-origin Squarespace cart injection~~ — superseded by the per-seat-permalink catalog restructure above; no longer needed.
- [x] ~~Document Squarespace webhook registration steps~~ — turned out not to apply: Squarespace's Webhook Subscriptions API is OAuth-only, so a plain site API key can't register a subscription (the admin's old "Settings → Advanced → Webhooks" toggle this assumed no longer exists/applies here). Replaced with a poller (`manage.py poll_squarespace_orders`, using a plain Orders-Read-Only API key) as the actual live order-sync mechanism — see `RUNBOOK.md` §5. Still no reconciliation path if the poller is down longer than its lookback window; that gap remains open. A real OAuth webhook integration is still possible later (registering a Developer Platform app) but nobody's done that work.
- [x] Remove the held-seat feature — stakeholder feedback was that it gets in the way: clicking through to checkout without completing the purchase left a seat stuck showing reserved to everyone else for the full 10-minute TTL, when all that's actually needed is tracking what's sold. Fixed: `SeatHold` model/migration, the `POST .../hold/` endpoint, and all `heldSeats`/hold-state UI (`App.jsx`, `ReservePanel.jsx`, `VenueMap.jsx`, `useSeatStatus.js`) removed entirely — Reserve now just links straight to checkout. Squarespace's own `Stock: 1` remains the sole overselling backstop (no soft lock in front of it anymore). Added `manage.py mark_seats_sold` alongside this so stakeholders can demo a populated chart without a real product/order behind every seat.
